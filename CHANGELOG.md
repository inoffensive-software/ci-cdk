## [Unreleased]

Nothing has been released yet. This section describes what the package provides at `0.0.0` on
`main`.

### Added

- Core: `Doc`, the ordered and style-annotated tree, with the `map`, `seq`, `scalar`, `block` and
  `tagged` constructors.
- Core: `fromValue`, the boundary parser that turns untyped data into a `Doc`. It rejects functions,
  cycles and values YAML cannot represent, and reports each problem as a `Diagnostic` with a path, a
  message and a hint.
- Core: `renderDoc`, the deterministic YAML emitter. Output is LF only, two-space indented, block
  style, never wrapped, and ends in exactly one newline. The header defaults to
  `# Generated by @inoffensive/ci-cdk. Do not edit.`; it carries no version and no timestamp.
- Core: `DiagnosticError`, `fail` and `formatDiagnostics` for errors raised while a document is
  lowered.
- Core: the `Value`, `Text`, `Serializer` and `ScalarStyle` types, used by providers and by the
  `raw` escape hatches.
- GitHub Actions: `workflow`, `job` and `step` builders, `render` and `toDoc`, and the `expr`,
  `script`, `matrix` and `needs` leaves.
- GitHub Actions: workflow triggers, permissions, concurrency, environment variables, defaults,
  cache mode, reusable-workflow calls, environments, job strategy and matrix, containers, services,
  job and step conditions, step concurrency and parallel steps.
- GitHub Actions: document validation for duplicate job ids, dangling `needs` and dependency cycles.
- GitLab CI: `pipeline`, `job` and `render`, covering `stages`, `stage`, `script`, `image`,
  `services`, `needs`, `rules`, `default`, `workflow`, `include`, hidden templates, `extends`,
  cache and `!reference`.
- Bitbucket Pipelines: `pipelineConfig`, `step`, `stage`, `parallel`, `pipe`, `finalStep` and
  `render`, covering `image`, `options`, `definitions`, `pipelines`, selectors, variables, caches,
  services, conditions, `oidc`, size and clone options.
- Corpus: pinned public configurations with recorded provenance. Eleven for GitHub Actions, three
  for GitLab CI and five for Bitbucket Pipelines.
- Gates: the corpus exhaustiveness gate holds the modelled vocabulary to the corpus keys and the
  `raw` ledger in both directions. The documented-grammar gate compares the modelled paths with the
  provider's schema and declares every gap with a reason and a category. It currently runs for
  GitHub Actions.
- Schema conformance tests for all three providers, against schemas vendored under
  `test/schemas/`.
- Release tooling: `docs/releases.md`, a generated `.github/workflows/release.yml` for npm trusted
  publishing, `pnpm ci:workflow` to regenerate every generated workflow, and `pnpm notes` to list
  commits since the last tag.

### Changed

- The emitted header is fixed text with no version and no timestamp, so publishing a release never
  changes generated output.

### Fixed

- Double-quoted scalars stay on one line, so a long expression or a value containing a newline does
  not change the emitted document shape.
- A string that spells a number stays a string at the boundary, so `"9090"` is emitted quoted and
  parses back as text.
- A bare event emits `null` rather than `{}`, matching how `push:` parses.

### Removed

- The GitHub Actions `image_version` leaf. It was not part of the documented workflow grammar; see
  [ADR 0012](docs/decisions/0012-drop-image-version.md).

## Provider support

| Subpath                                   | Provider            | Status      |
| ----------------------------------------- | ------------------- | ----------- |
| `@inoffensive/ci-cdk/github-actions`      | GitHub Actions      | Supported   |
| `@inoffensive/ci-cdk/gitlab-ci`           | GitLab CI           | In Progress |
| `@inoffensive/ci-cdk/bitbucket-pipelines` | Bitbucket Pipelines | In Progress |

"Supported" means the provider reproduces its corpus as parsed data, the exhaustiveness gate is
clean, and the documented-grammar gate is in place. "In Progress" means the vocabulary and corpus
exist and the gates are still being completed. A support claim belongs to the tag it was read at;
see [`docs/releases.md`](docs/releases.md).

### GitHub Actions compatibility

| Area                | Support                                                                   |
| ------------------- | ------------------------------------------------------------------------- |
| Identity and `on:`  | Workflow name, run name, every documented event, event filters and inputs |
| Permissions         | Workflow and job level, per scope, plus `read-all` and `write-all`        |
| Execution           | Jobs, needs, outputs, conditions, timeouts, concurrency, environments     |
| Steps               | `run`, `uses`, `with`, `env`, `shell`, conditions, ids, parallel groups   |
| Strategy and matrix | Matrix, `fail-fast`, `max-parallel`                                       |
| Containers          | Job containers and service containers with credentials, env and volumes   |
| Escape hatch        | `raw` on workflows, jobs and steps for keys outside the vocabulary        |

Not supported: matrix `include` and `exclude`, `workflow_call` outputs and secrets, `runs-on` as
`{ group, labels }`, the `snapshot` job key, and service `command` and `entrypoint` overrides. The
provider page records the reasons and the schema gaps.
