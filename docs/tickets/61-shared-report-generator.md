# 61: One provider-report generator

**Spec:** none (refactor found by the sharing sweep)

**What to build:** The tables a provider page carries — corpus coverage by grammar area, the ledger, and
the documented-grammar block — are rendered by one provider-neutral module in `test/corpus/report.ts`.
Bitbucket Pipelines landed by copying GitHub Actions' generators, so this consolidates two real copies
rather than anticipating a copy, and leaves the module ready for the third page.

**Blocked by:** None (can start immediately). It must land before GitLab's provider page (44) is
written, or the cost is paid a third time.

**Status:** ready-for-agent

- [ ] A shared module owns markdown table formatting, the coverage table, the open-gaps block, the
      documented-grammar block and the marked-block extraction a document test uses.
- [ ] Each provider keeps only its own grammar-area map, its entry list and its declared rows; the
      renderers take those as parameters and contain no CI nouns.
- [ ] Both provider pages are generated by the shared module, byte-identical to today's documents, so
      their document tests still pass unchanged.
- [ ] A provider with no page yet needs no new code to add one beyond its area map and its lists.
- [ ] `pnpm check` passes.

**Where GitLab plugs in:** 44 supplies `GRAMMAR_AREAS`, a `COVERAGE_TABLE` and a `GRAMMAR_TABLES` list
beside its own `ENTRIES`, `COVERAGE_DEBT`, `GAPS` and `OVERCLAIMS`, then calls `renderCoverageTable`,
`renderOpenGaps` and `renderDocumentedGrammar`. A page that models each key once needs no `keyOf`, no
`positionsNote` and no `lead`; one that repeats its grammar copies Bitbucket's `COVERAGE_TABLE`, which
sets all three. No generator code changes.
